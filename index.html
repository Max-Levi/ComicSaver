ComicSaver — Technical Documentation

Last updated 2026-09-25.

1. Overview 2. Architecture 3. Image collection 4. Choosing images 5. Saving 6. Settings 7. Chrome extension 8. Requirements 9. Maintainer notes 10. QA regression checklist

1. Overview

ComicSaver is a single-file, client-side web application for bulk-saving the images from a page — built for downloading manga/comic chapters a page at a time. Paste a page URL, review the images as thumbnails, drop the ones you don't want, then download the rest.

The entire application — markup, styles, and logic — is contained in one HTML file. There is no build step for the web version, no backend, no account system, and no database. A companion Chrome extension scrapes the open tab directly and saves through the downloads API.

2. Architecture

  • All application state is held in a single in-memory state object (images with per-image kept flags, baseUrl, UI flags). Rendering is performed by small render functions (renderGrid, renderFailedList) that rebuild their panes from that state.
  • Two compile-time flags select the build variant from the same source: IS_QA (QA site: red badge, “ — QA” title, “ QA” stamped into names) and IS_EXTENSION (Chrome extension app page).
  • Appearance is controlled by a data-theme attribute on the <html> element (dark default, light follows the device), persisted per device.
  • Thumbnails and downloads request images with referrerpolicy="no-referrer" / referrerPolicy: 'no-referrer', which defeats the most common kind of hotlink protection (servers that 403 on a foreign Referer but allow a missing one).

3. Image collection

  • Website: the pasted page is fetched and parsed with DOMParser. The extractor collects <img> src (falling back through data-src and other lazy-load attributes), the largest candidate of each srcset/data-srcset, the largest <source> inside <picture>, and — when “Collect linked images” is enabled — <a> links whose href points at an image file.
  • CORS: browsers only let a page read another site's content if that site allows it. When a page can't be fetched directly, ComicSaver offers a paste-page-source fallback (view source, copy, paste).
  • Extension: a content script runs the same extractor rules against the live tab's DOM, so there is no fetch and no CORS involved; the payload travels to the app page via chrome.storage.session.
  • Security: every candidate URL is resolved against the page's base URL first, and only http(s) (plus data: images) survive — javascript: URLs are rejected, including obfuscated ones with embedded tabs or newlines, which browsers silently strip during URL parsing. The failed-downloads list only links http(s) and data:image URLs; anything else renders as inert text.
  • Duplicates are removed; the surviving images keep page order.

4. Choosing images

  • Everything starts selected. Clicking a thumbnail or its checkbox toggles it; Select all / Select none handle big batches. The header shows a live “N of M selected” count.
  • Only kept images are downloaded, in page order.

5. Saving

  • Website (Chrome/Edge): the File System Access API (showDirectoryPicker) asks for a folder once; each batch becomes a new real subfolder inside it. Configuration offers a “reuse folder” mode so the picker doesn't reappear every batch.
  • Website (other browsers): falls back to anchor downloads into the Downloads folder, with files named <folder>_<file> (browsers flatten “/” in download names, so pages can't create subfolders that way).
  • Extension: saves through chrome.downloads.download straight into the Downloads folder. Every file is renamed to <name>_001.ext, <name>_002.ext, … (zero-padded, original image type kept) so the batch stays together and sorts in page order. conflictAction: 'uniquify' keeps repeat downloads from overwriting. Caveat: Chrome silently ignores the requested file name when another extension manages downloads (it registers an onDeterminingFilename listener — Chromium issue 579563); ComicSaver detects this after the batch and says so instead of claiming the rename worked.
  • Batch naming: the name field comes pre-filled from the last batch, incrementing any trailing number (Chapter 3 → Chapter 4; no number → appends “ 2”; first ever → batch-1) — keep it or type over it. The last-used name is kept in the browser's localStorage, and the effective name is captured at batch start so typing during a download can't corrupt the increment chain.
  • Individual fetch failures (CORS, hotlinking, dead links) land in a failed list after the batch with links, so they can be grabbed by hand. In the extension, an “Open Downloads folder” button appears after each successful batch (web pages are forbidden from opening the file manager).

6. Settings

All settings live in the browser's localStorage — no files, no sync:

  • comicsaver-theme — dark / light appearance.
  • comicsaver-last-folder — last batch name, feeding the auto-increment.
  • comicsaver-linked-images — 1 collects linked image files too.
  • comicsaver-picker-mode — website folder-picker reuse / ask.
  • comicsaver-ext-update-dismissed — extension self-update banner dismissal per version.

7. Chrome extension

  • Manifest V3. Permissions are minimal: activeTab, scripting, downloads, storage — no broad host access.
  • Flow: toolbar click → background worker injects the content script into the live tab → scraped payload via chrome.storage.session → app tab (the familiar ComicSaver UI, built from the same source with IS_EXTENSION) opens.
  • MV3 extension pages forbid inline scripts, so the build externalizes the script to app.js.
  • Self-update: unpacked extensions don't auto-update, so the app page fetches ext-version.json from the site on every open and shows a gold banner when a newer version exists, with a Download button, a How to update step-by-step guide (update the same folder so settings survive, then reload on chrome://extensions), and per-version dismiss.

8. Requirements

  • Website folder picker: Chrome or Edge (File System Access API). All other modern browsers get the Downloads-folder fallback.
  • Extension: Chrome (or another Chromium browser with chrome.downloads).
  • The sites are plain static pages — JavaScript required, no network beyond the target page and its images.

Updating the ComicSaver extension

Unpacked extensions can't update themselves, so it takes a minute by hand. Your settings live in the browser — but only if you update the same folder, not a fresh copy.

  1. Download the new version. Use the Download button in the gold banner (or this link). It saves a .zip file, usually into your Downloads folder.
  2. Find your ComicSaver folder — the one you picked with “Load unpacked” when you first installed it.
  3. Empty the folder, then unzip the download into it. Delete everything inside your ComicSaver folder first (this clears out old files), then unzip the downloaded .zip there. On a Mac, double-click the zip to expand it, then move the new files into the folder.
  4. Reload the extension. Type chrome://extensions into Chrome's address bar, find ComicSaver, and click the reload ⟳ button on its card. (Chrome won't let a page open that address for you.)
  5. Reopen ComicSaver. If the gold banner is gone, you're on the new version.

ComicSaver help

What it does

ComicSaver takes the URL of a page, lists every image on it as thumbnails, lets you drop the ones you don't want, then saves the rest into a brand-new folder — one folder per batch.

The three steps

  • Load a page. Paste a URL and press Load images. ComicSaver reads the page and pulls out its images: <img> tags (including srcset and lazy-load attributes), <picture> sources, and — if enabled in Configuration — links that point at image files.
  • Choose images. Everything starts selected. Click a thumbnail or its checkbox to deselect it. Select all / Select none are there for big batches.
  • Save to a folder. The name is filled in for you from your last batch, incrementing any number at the end (e.g. Chapter 3 → Chapter 4) — keep it or type your own. The first batch ever is called batch-1.

Where the files go

  • In Chrome and Edge you'll be asked to pick a folder once; each batch then becomes a new subfolder inside it.
  • Other browsers save into your normal Downloads folder, with every file named <folder>_<file> (browsers don't let a page create subfolders there) so each batch stays grouped together.

Why some pages won't load

Browsers only let a page read another site's content if that site allows it (CORS). Many sites don't. When a page can't be fetched directly, ComicSaver offers the paste-source workaround: view the page's source (Ctrl/Cmd+U), copy it, and paste it in. Previews and downloads request images without a referrer, which defeats the most common kind of hotlink protection; sites that insist on their own address as the referrer can't be loaded by any web page — those files land in the failed list after the batch so you can grab them by hand. There is also a ComicSaver Chrome extension that reads the open tab directly, so the URL step and the paste workaround go away entirely — and its downloads are saved with sequential file names.
